# EzJournal — public site

This repository is the **published output** of the EzJournal app (SPEC §9). It
contains only entries that were explicitly published — public posts as
plaintext, private posts as AES-256-GCM ciphertext. The app and its database
are **not** in this repository, and never will be.

Deployed as a plain GitHub Pages site: no build step, no server, no
third-party requests at runtime. Everything (fonts, scripts, styles, sounds)
is self-hosted under `/assets/`.

## Layout (SPEC §9.1)

```
/                       index.html — SPA shell (this file's sibling)
/assets/app.css         sci-fi theme (ported from blogger_theme/preview.html)
/assets/app.js          renderer, hash router, private-vault unlock, sound layer
/assets/argon2.js       Argon2id (RFC 9106) — pure JS + optional wasm loader
/assets/crypto.js       WebCrypto AES-256-GCM envelope handling (SPEC §10.2)
/assets/fonts/          vendored woff2 fonts (see assets/fonts/README.md)
/index.json             public post index: {posts: [{slug, title, date, tags, excerpt}]}
/posts/<slug>.json      public post content: {slug, title, date, tags, html}
/posts/<slug>.html      pre-rendered static page — fully readable with JS disabled
/private/manifest.json  {version, kdf, salt, params} — no post metadata whatsoever
/private/index.enc      encrypted index of private posts (an envelope)
/private/<opaqueId>.enc encrypted post envelopes; filenames leak nothing
/ci/leak-guard.mjs      CI backstop (SPEC §10.4) — see .github/workflows/leak-guard.yml
/ci/make-fixtures.mjs   dev-fixture generator (documents the exact file formats)
/test/                  crypto test suite: `node test/run.js`
/.nojekyll              tells GitHub Pages to serve files verbatim
```

## How the app writes into this repo

The EzJournal app publishes via the GitHub Contents API (fine-grained PAT,
this repo only). One publish = one batched commit that:

1. writes `posts/<slug>.json` and the pre-rendered `posts/<slug>.html`
   (public), **or** `private/<opaqueId>.enc` (encrypted),
2. regenerates the affected index (`index.json` or `private/index.enc`),
3. never touches anything else.

The app has no code path that writes plaintext under `/private/`. The
`leak-guard` workflow is the independent backstop: every push is rejected
unless all files under `/private/` parse as valid v1 envelopes and no file
outside the site allowlist was added. Treat everything committed here as
permanent — un-publishing removes files, not history, forks, or caches.

## Private posts

- Envelope format (SPEC §10.2): AES-256-GCM content encryption; per-post
  random content key, wrapped by the vault key; vault key derived from the
  passphrase with **Argon2id m=65536 KiB, t=3, p=1** (`private/manifest.json`).
- The browser decrypts locally: `Private` → passphrase → a few deliberate
  seconds of key derivation → the private index and posts decrypt on demand.
- The key stays in memory; "Remember on this device" stores the derived key
  (never the passphrase) in `sessionStorage` for the tab's lifetime only.
- A wrong passphrase is a GCM authentication failure: one clean "Incorrect
  passphrase" message, never a partial render.

The checked-in sample content was generated by `node ci/make-fixtures.mjs`.

## Tests

```
node test/run.js          # full suite, incl. m=65536 argon2 vectors (~15 s)
node test/run.js --fast   # skips the slow full-memory vectors
node ci/leak-guard.mjs --local   # run the leak guard against the working tree
```

The suite verifies the pure-JS Argon2 against the phc-winner-argon2 and
RFC 9106 known-answer vectors byte-for-byte, plus Blake2b against OpenSSL and
a full envelope encrypt→decrypt round-trip through the exact code path the
site uses. Argon2 parity with the app (SPEC §10.6) hangs off these vectors —
run them in CI on both sides.
